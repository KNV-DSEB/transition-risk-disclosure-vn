# DATA PROVENANCE PROTOCOL
Version: 0.1
Created: 2026-10-02 by Claude
Status: OPERATIONAL. Implements the data rules in `CLAUDE.md` and Constitution §11.

## 0. Scope and boundary
This protocol covers **how** data and sources are stored, identified, versioned, corrected and excluded. It does **not** set scientific rules such as source tiers allowed in the primary analysis, facility-to-firm aggregation, temporal alignment or exclusion criteria. Those are frozen at Gate 3 through `DECISION_LOG.md`. Where this file needs a scientific rule, it leaves a placeholder that points to the decision that must supply it.

## 1. Data layers
Folders are created when the first file of that layer exists. No data exists yet.

| Layer | Path | Rule |
|---|---|---|
| Raw | `data/raw/<source_id>/` | Immutable. Files are stored exactly as retrieved. Never edited, renamed in place or overwritten. |
| Manual entry | `data/manual/` | Human-entered tables (e.g., pilot sheets). Each change is versioned. |
| Interim | `data/interim/` | Outputs of documented transformations. Reproducible from raw + code. |
| Processed | `data/processed/<dataset>_v<x.y>/` | Analysis-ready, versioned datasets. A frozen version is never modified; changes produce a new version. |
| Outputs | `outputs/<exp_or_analysis_id>/` | Tables and figures generated by code only. |

## 2. Source acquisition
Every retrieved file (regulation, allocation decision, filing, financial statement, report, dataset) gets a row in `SOURCE_MANIFEST.csv` **before** it is used:
- `source_id` format: `SRC-<TYPE>-<NNN>`, e.g., `SRC-LAW-001`, `SRC-ALLOC-001`, `SRC-FS-014`.
- `sha256` of the stored file.
- `retrieved_date` and `retrieved_by`.
- `url_official` and, where possible, an archived copy (`url_archive`). Government URLs may change, so the local raw copy is the reference.
- For regulations: `status_as_of` (in force / amended / superseded / repealed) **with the date it was checked**, plus `amends_or_supersedes` and `amended_or_superseded_by`.
- `source_tier` uses the tiers in `DATA_FEASIBILITY_MATRIX.xlsx` → `Source_Hierarchy`.

`SOURCE_MANIFEST.csv` columns:
`source_id, source_type, title_original, title_en, issuer, document_number, issue_date, effective_date, status_as_of_date, status_as_of, amends_or_supersedes, amended_or_superseded_by, language, url_official, url_archive, retrieved_date, retrieved_by, local_path_raw, file_format, sha256, source_tier, used_for, access_restrictions, notes`

Suggested `source_type` values: `law, decree, decision, circular, official_list, allocation_decision, corporate_filing, financial_statement, annual_report, sustainability_report, exchange_disclosure, dataset, methodology_doc, other`.

## 3. Identifiers
- **Facility:** use the identifier from the official covered-facility list when one exists. Otherwise assign `FAC-NNN` and keep a crosswalk to every name variant seen, with the source of each.
- **Firm:** prefer the enterprise registration / tax code (mã số doanh nghiệp). The ticker is an attribute, not the key, because listings change.
- **Evidence:** every extracted value carries `source_id` + locator (article / clause / table / row / page).

## 4. Variable lineage
Every variable used in analysis has an entry in `DATA_FEASIBILITY_MATRIX.xlsx` → `Variable_Catalog` (later a data dictionary), giving the definition, unit, time reference, source priority, transformation rule, missingness policy and validation check. A derived variable states its formula and its input variable IDs.

## 5. Manual corrections
Every manual change to a value obtained from a source is logged in `data/manual/MANUAL_CORRECTIONS_LOG.csv` (create on first use):

`correction_id, date, corrected_by, dataset_and_version, record_key, field, old_value, new_value, evidence_source_id, evidence_locator, reason, reviewed_by, review_date`

Corrections without an evidence source are not allowed. Use a missingness code instead.

## 6. Exclusions
Every facility, firm or record dropped from a sample is logged in `data/manual/SAMPLE_EXCLUSION_LOG.csv` (create on first use):

`exclusion_id, date, record_key, level (facility/firm/record), chain_link_failed, reason_code, evidence, excluded_by, rule_reference (DEC/ISS), reversible (Y/N), notes`

Reason codes and exclusion rules are scientific decisions (placeholder: frozen at Gate 3). Until then, record reasons in free text and leave `reason_code` empty.

## 7. Missingness codes
Values are never imputed silently. Use:

| Code | Meaning |
|---|---|
| `NA_NOT_PUBLISHED` | Source type exists but this value is not published |
| `NA_RESTRICTED` | Exists but access is restricted |
| `NA_NOT_APPLICABLE` | Not applicable to this unit |
| `NA_NOT_YET_COLLECTED` | Not yet searched |
| `NA_AMBIGUOUS` | Sources found but the value cannot be determined unambiguously |
| `NA_CONFLICT` | Sources conflict; logged as a blocker |

Any estimation or imputation is a separate, named derived variable with a documented method. It never overwrites the original field.

## 8. Units, scale and currency
- Every numeric field has an explicit unit column or a unit stated in the catalog.
- Emissions in tCO2e, with gases and scope/boundary recorded.
- Financial values: record currency **and scale** as reported (đồng / nghìn đồng / triệu đồng / tỷ đồng) before normalizing.
- Currency conversions record the rate, its source and its date.

## 9. Time references
Every value records its time reference: compliance period, fiscal year (with fiscal year-end date), or document issue/effective date. **Alignment rules between compliance periods and fiscal years are scientific (placeholder: frozen at Gate 3).**

## 10. Regulatory text versions
Extraction targets "the provision as in force at reference date t". Record the reference date for every extracted policy field and the amendment chain used to determine it.

## 11. Checks before freezing a dataset version
- [ ] All raw inputs listed in `SOURCE_MANIFEST.csv` with hashes.
- [ ] Rebuild from raw + code reproduces the dataset (hash match).
- [ ] Every variable is in the catalog with unit and time reference.
- [ ] Manual corrections and exclusions logged.
- [ ] Missingness report generated.
- [ ] Version tag and `DECISION_LOG.md` entry recorded.

## 12. Restricted data (added 2026-10-03, ISS-010)
Applies to any data obtained through non-public routes, e.g. facility inventories via an official or insider contact.
- Store only under `data/restricted/` (git-ignored). Never commit to git and never push to any remote, including private remotes, unless the data owner's written terms allow it.
- **Do not upload, paste or describe record-level restricted data to cloud AI tools (Claude, ChatGPT, others) unless the data owner's terms explicitly permit it.** AI agents may receive only schema descriptions and aggregate, non-identifying summaries that the terms allow.
- Record for each restricted dataset (in `SOURCE_MANIFEST.csv`, with access_restrictions filled): data owner, legal basis/agreement, permitted uses, retention and destruction terms, publication restrictions, who holds the copy.
- Results derived from restricted data are published only at the aggregation level the agreement allows.
- Until such an agreement exists, the status of facility emissions remains **NOT PUBLICLY ACCESSIBLE**, and no restricted data enters the project.
